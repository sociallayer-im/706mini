## 共用组件层面的变化

- ui-button：那一轮 text 与 danger 的可见面由透明改中性底；随后所有 secondary 统一浅灰底，canvas 语境也不再改白色。当前 text 已恢复透明，仅评论回复重新使用；danger 保留浅灰底与危险色。
- ui-button：取消了 align=start 对所有变体去掉左右内边距的覆盖；当前只给透明 text 恢复左对齐零内缩，避免影响有底色按钮。
- ui-identity-row：修正原先只读实例也会发 press 的问题，只有 interactive=true 才发出导航事件。
- 日历展开箭头曾跟随文字按钮批量改为浅灰整行按钮；用户指出过重后，已恢复无底色箭头，压缩可见行高，透明点击区域仍保留。

## 主按钮审计：待用户确认，不在本次修改

“黄色主按钮”和“整行宽度”是两项独立设置。发布推荐原先已为 primary，截图中的问题是 grow 放在非横向 flex 容器里不能铺开；本次只给它明确的 block。

| 待确认位置 | 当前情况 | 建议 |
| --- | --- | --- |
| 备用手机号／邮箱验证码登录：获取验证码 | secondary，区别于已统一的手机号验证页面 | 评估是否改为标准 primary |
| 报名／候补／申请确认弹窗 | 已是 primary；与发布推荐共用 submitSheet，但仍是 grow，没有 block | 若采用同一提交规范，改为整行主按钮 |
| 评论发布、举报／反馈提交、邀请成员／管理员授权确认弹窗 | 已是 primary；共用 submitSheet，仍是 grow | 若采用同一提交规范，改为整行主按钮 |
| 支付弹窗、发送修改意见弹窗 | 已是 primary；grow 位于普通内容流中 | 明确 block 才能保证整行宽度 |
| 保存海报 | 已是 primary；外层 flex-direction:column，grow 分配纵向空间，不保证横向铺开 | 评估整行主按钮 |
| 备用验证码登录：登录、平台管理员页：授权管理员 | 已是 primary；grow 所在容器未采用横向 flex | 评估整行主按钮 |

原已正确使用 primary 的继续编辑、去付款、审核通过、签到、接受邀请等卡片内主操作不属于错误；它们可以使用紧凑尺寸。存草稿、添加、换几个、生成海报也不因为这次审计而升为黄色。
