# 按用户类型组织的业务路径与走查清单

日期：2026-10-24。用于规划开发者栏目中的完整 journey，区别于单页预览目录。依据当前原生小程序路由、账号流程和离线状态机整理；列为走查路径不代表真实授权、短信、支付及后端业务均已验收。本次整理目录，不自动新增全部演示入口。

## 用户分类

游客、首次登录、已完成 onboarding 是账号阶段；参与者、发起人、空间／组织管理员、平台审核者是业务角色。同一用户可以同时拥有多个业务角色，角色权限按具体活动或实体判断。

| 用户类型 | 主要目标 | 完整路径 |
| --- | --- | --- |
| 游客 | 先了解社区 | 打开小程序 → 切换城市／浏览动态和活动 → 查看活动、成员、空间 → 点击关注、报名或发布 → 当前页登录层；关闭后继续浏览 |
| 首次登录用户 | 建立账号与个人主页 | 参与操作触发登录 → 微信登录 → 验证手机号 → 三步 onboarding → 欢迎页 → 本人主页 → 现有编辑资料页 → 保存并浏览主页 → 分享主页；可主动继续原操作 |
| 老用户／活动参与者 | 找到活动、认识人并参与 | 登录后直接回到原操作 → 发现／筛选活动 → 查看详情 → 报名 → 必要时等待审核／付款 → 报名凭证 → 查看参与方式；也可浏览成员 → 关注 → 查看关注列表 |
| 活动／专题发起人 | 发布内容并管理参与 | 创建活动 → 存草稿 → 继续编辑 → 预览 → 提交发布审核 → 查看进度 → 如被退回则修改重提 → 发布后分享 → 查看报名 → 必要时报名审核 → 参与管理；专题另走创建、关联活动、确认和审核路径 |
| 空间／组织管理者 | 维护节点、处理关联事务 | 有权限的管理入口 → 创建空间 → 编辑空间 → 浏览空间主页及活动；查看待审关联活动 → 审核；Owner 可邀请管理员 → 对方接受 → 协作管理 → 撤销权限 |
| 平台审核者 | 处理发布审核 | 管理员待办／消息 → 活动或专题审核详情 → 查看内容与关联方 → 通过或附理由退回 → 发起人收到结果 → 查看新一轮审核记录 |

## 建议的开发者走查条目

每条应能从业务起点开始操作，明确起始账号、切换角色的时机、预期状态、终点与重跑方式。使用现有页面和保存逻辑，不复制走查专用业务页面。

| 编号 | 归属 | 走查路径 | 必看分支与终点 |
| --- | --- | --- | --- |
| J01 | 游客／新用户 | 浏览 → 点击关注／发布 → 登录 → 手机验证 → onboarding → 本人主页 → 编辑资料 → 分享主页 | 登录层关闭、验证码错误、设置中断续填、选填项留空；分享接收方打开公开主页 |
| J02 | 老用户 | 退出登录 → 点击参与操作 → 微信登录 → 回到原操作 | 不重复 onboarding；资料已完成但手机号缺失时只补验证 |
| J03 | 成员 | 我的／本人主页 → 编辑资料 → 保存 → 返回主页 → 分享 | 全部编辑入口复用同一页；签名 30 字、介绍 300 字；保留换行；手机号不公开 |
| J04 | 参与者 | 发现／筛选 → 活动详情 → 免费免审报名 → 凭证 → 参与方式 | 成功确认前不显示私密参与信息；重复点击不重复报名 |
| J05 | 参与者＋发起人 | 提交报名申请 → 发起人审核 → 参与者查看结果 | 通过、拒绝；审核通过且需付费时进入待付款，不能直接视为报名成功 |
| J06 | 参与者 | 付费报名 → 如需审核先审核 → 待付款 → 支付 → 报名凭证 | 支付成功、失败、取消和超时；当前离线模拟支付不能替代真实支付验收 |
| J07 | 多名参与者 | 满员 → 加入候补 → 已报名者取消／占位超时 → 候补递补 → 如需审核或付款继续处理 | 关闭候补时不可加入；递补不一定直接确认；取消后参与方式访问失效 |
| J08 | 发起人 | 创建活动 → 填写内容与参与规则 → 存草稿 → 继续编辑 → 预览 → 提交发布审核 | 草稿恢复、校验失败、提交失败保留输入、提交后进入审核进度 |
| J09 | 发起人＋审核者＋参与者 | 活动提交 → 各审核方处理 → 发布 → 分享活动 → 接收方查看并报名 | 发布审核与报名审核分开；不同角色操作同一个活动；未通过的内容不应公开 |
| J10 | 发起人＋审核者 | 收到退回理由 → 进入原活动编辑页 → 修改 → 重提 → 新一轮审核 → 发布 | 保留审核记录；旧轮次不能决定新版本；已发布活动修改规则另行确认 |
| J11 | 发起人 | 我的活动 → 报名管理 → 查看申请与已确认成员 → 审核／签到／联系 → 处理取消 | 联系信息必须有授权；付费取消和退款规则尚需确认，不作为已完成退款流程 |
| J12 | 有创建权限的管理者 | 管理 → 创建节点／空间 → 编辑资料 → 空间主页 → 分享／查看关联活动 | 创建权限、必填名称和城市、选填信息补充；普通成员不获得管理能力 |
| J13 | Owner＋受邀管理员 | 空间管理 → 邀请管理员 → 对方查看邀请 → 接受 → 协作管理 → Owner 撤销权限 | 接受前无新权限；邀请失效、撤销后旧入口失效；Owner 与 Admin 权限不同 |
| J14 | 专题发起人＋相关审核者 | 创建专题 → 编辑 → 关联活动 → 提交 → 平台／组织审核及关联活动发起人确认 → 发布 → 专题详情 → 活动报名 | 关联方拒绝、无有效关联活动、退回重提；专题和活动的审核范围不同 |
| J15 | 所有已登录角色 | 收到消息 → 打开对应活动／报名／审核对象 → 处理 → 返回列表 | 消息已读、跳转对象正确、处理后状态刷新、对象失效或权限撤销 |

## 活动生命周期与角色交接

主链路：发起人创建／编辑 → 提交 → 审核方处理 → 发布 → 发起人或成员分享 → 参与者报名 → 如有需要由发起人审核报名 → 如有需要由参与者付款 → 确认报名 → 获取参与方式 → 发起人管理参与。

活动发布审核按关联关系可能涉及平台、组织与空间，不应把某一方通过等同于全部通过。审核者通过的是活动内容；发起人审核的是某个报名申请。

当前离线模型的核心状态：

- 活动：草稿 DRAFT → 审核中 IN_REVIEW → 已发布 PUBLISHED；退回为 CHANGES_REQUESTED，修改后重新提交。取消为 CANCELLED。自然结束由时间判断，不能与取消混同。
- 报名：需审核时先 REQUESTED；通过后免费为 CONFIRMED，付费为 APPROVED_AWAITING_PAYMENT，支付成功后才 CONFIRMED。拒绝为 REJECTED。
- 满员且允许候补：WAITLISTED → 有名额后进入所需的审核／付款／确认步骤。待付款超时为 EXPIRED；主动取消为 CANCELLED。
- 管理邀请：PENDING → ACCEPTED；权限撤销为 REVOKED。邀请和接受后的有效管理角色是不同记录。

## 每条路径的信息交接

| 对象 | 采集／留存 | 流转与可见范围 |
| --- | --- | --- |
| 账号与主页 | 微信登录身份、手机号验证状态；昵称、头像、城市、签名、自我介绍、选填链接 | 手机号仅本人账号流程使用；公开主页展示用户选择填写的公开信息；签名与完整介绍分别保存 |
| 活动 | 内容、图片、时间、地点、关联空间／组织、人数、价格、是否审核报名、是否候补、私密参与方式 | 草稿由有权编辑者继续修改；提交生成审核任务；发布后公开活动内容；私密参与方式需确认报名及相应权限 |
| 发布审核 | 审核对象与版本／轮次、审核方、决定、理由、处理者、时间 | 审核方处理对应任务；发起人在进度页看到结果并回到原表单修改 |
| 报名与票务 | 活动 ID、参与人、报名填写内容、隐私确认、联系授权、审核与支付状态 | 发起人查看自己的活动报名；参与者查看自己的凭证；支付、审核、候补状态共同决定可参与状态 |
| 空间与管理权限 | 名称、城市、介绍、开放时间、地址、Owner、管理员、邀请状态 | 创建者获得对应管理角色；受邀者接受后获得相应权限；撤销后入口和服务端权限同步失效 |
| 消息与分享 | 业务对象、通知类型、阅读状态；公开落地页路径与对象 ID | 通知带用户到有权查看的业务对象；分享带接收者到公开页面，参与动作再触发登录 |

上述为前端已有数据与业务需求的整理，具体服务端留痕和权限须结合真实接口联调确认。

## 建议先走通的五条主线

1. J01：新用户身份与主页建立。开发者栏目已提供完整流程入口。
2. J08＋J09：草稿 → 编辑 → 发布审核 → 分享 → 他人报名，串起跨角色主链路。
3. J04＋J05＋J06：免费免审、需审核、付费报名三个主要分支。
4. J07：候补、取消、超时与递补。
5. J12＋J13：创建空间、补充资料与管理权限交接。
