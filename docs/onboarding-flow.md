# 首次登录与个人主页设置

2026-10-24。本轮实现位于原生小程序，保留关注／发现的设计系统；不修改网页原型。

## 用户路径

- 游客可以浏览关注、发现、活动、成员与空间。游客点击我的／消息时，直接在原浏览页面打开同一套登录覆盖层，关闭后保留原页面及当前选中 tab。外部直接打开未登录的我的／消息页也自动弹出登录层，关闭后回到关注页；不展示中间登录按钮卡片。
- 报名、推荐、评论、关注及发起入口检查账号。原页面上覆盖可关闭的全屏登录层，以半透明模糊背景保留上下文；缺手机号或资料的已登录用户继续在同一层完成设置。关闭可继续浏览，不覆盖原页面的活动草稿。
- 登录主文案为「探索生活的更多可能性」，默认使用全宽标准主按钮「微信一键登录」。返回箭头复用 navigationTop/navigationHeight/menuHeight，与微信胶囊居中对齐；横向使用主导航 pageGutter。顶部不再展示小字 706。
- 微信登录是默认入口。登录身份不等于昵称、头像或微信号；头像使用 chooseAvatar，昵称使用 nickname 输入，不自动获取微信号。
- 缺少已验证手机号：输入大陆手机号 → 获取短信 → 验证 → 设置个人主页。
- 三个问题依次为「我们想要了解你」「你平时在哪里？」「请介绍一下自己吧！」。第一步同时设置头像、昵称和一句签名。昵称、城市及隐私确认必填；头像、签名和介绍可稍后补充。
- 一句话介绍最多 80 字，用于成员卡片；完整介绍最多 300 字，保留文字与换行。编辑资料使用相同限制。移除兴趣选择和主页兴趣标签，不根据自我介绍生成标签，也不覆盖旧资料中的兴趣数据。
- 首次完成展示「已完成！欢迎你」，点击「开始吧」进入自己的公开主页浏览。用户名在头像右边；提供编辑资料入口，签名和介绍为空时仅本人看到补充入口，点击可定位编辑字段。作品、社交链接等其他资料可在编辑页继续补充。
- 日常资料编辑只有现有的 `pages/edit-profile/index` 页面。主页、补充空白、我的和设置入口全部进入该页；补充入口只传 field 定位字段，复用整页的布局、字段、校验、草稿与保存逻辑。已完成账号访问旧 onboarding 链接也重定向到该页。旧 onboarding 的普通表单和资料保存后欢迎页分支已移除，首次引导仍由账号覆盖层承担。
- 已完成资料但缺手机的老账号，只补手机；手机与资料均完成的账号直接返回来源。
- 来源保存 30 分钟，按传输模式隔离，登录后绑定当前账号。新用户主页提供「继续刚才的操作」，由用户主动返回原入口；返回报名会重开表单，不提交报名；关注按原先请求执行。回流重新读取活动状态。
- 手机不进入公开成员 DTO；资料草稿按账号隔离，手机号和验证码不写入本地草稿。中途退出可继续浏览。

## 接口与联调边界

微信身份沿用 POST /api/v1/auth/wechat_miniprogram。私有账号状态单独读取 GET /api/v1/users/me，不往公开 person 映射中添加手机号。

手机号依照仓库 soon-call.md 的 bind_phone 约定接线：已登录 Bearer 请求 POST /auth/request_phone_code 与 POST /auth/verify_phone_code，带 context=bind_phone。发送间隔 30 秒，错误／小时限流可重试提示。验证后重新读取本人账号，服务端未确认手机号则不进入下一步；响应账号改变或出现 merged 时拒绝在客户端切换账号。

本轮无法联网取得后端源码，以上补绑接口的实际部署和验码上下文仍需联调确认。不得用匿名手机号登录替代补绑，不得向用户资料直接 PATCH 一个自称已验证的手机号。404 显示尚未开通并允许返回浏览。当前没有已确认的微信手机号授权兑换端点，因此未伪造 getPhoneNumber 成功逻辑。

个人资料仍 PATCH /users/me，保存 nickname、image_url、城市、bio、introduction 和 onboarded。后端必须独立校验绑定、权限与资料完成条件；前端入口检查不替代服务端约束。隐私确认沿用现有接口，正式政策版本的服务端留痕尚需核对。

## 2026-10-26 登录页细化

- 两项独立勾选默认未选：可选活动消息提醒，必选用户协议与隐私政策；共用 ui-checkbox，新增 custom slot 和 secondary 文本外观，法律链接 catchtap 不切换勾选。
- 协议文件：miniprogram/content/user-agreement.js、privacy-policy.js。均为结合现有产品流程整理的草稿模板，显式标明运营信息等待补充；不是直接复制他人产品协议，也不宣称正式发布。lib/legal-documents.js 为统一阅读适配器，原登录覆盖层切换文档视图，返回保留登录进度与勾选状态。
- 微信身份使用 wx.login；头像仍使用 chooseAvatar，昵称仍使用 type=nickname，不能模拟旧 getUserProfile 自动授权行为。
- 活动提醒勾选后，登录点击事件首先调用 requestSubscribeMessage（在异步登录前，保持用户手势上下文），真实模板 ID 配置在 miniprogram/config.js 的 activityReminderTemplateIds。未勾选、离线演示、无模板、拒绝、系统失败均不伪装为微信接受授权。订阅失败不阻断登录；应用偏好独立保存到 notification_preferences.enabled。
- 模板 ID 不能从通用模板复制：必须在本小程序微信后台选择报名成功、活动开始提醒模板后取得。目前数组为空，真实系统订阅弹窗和服务端模板发送／回执还需完成配置及联调。客户端勾选和系统接受均不保证长期、无限次推送。设置内当前能关闭应用提醒，微信系统订阅权限由微信管理。
- 编译验证：94 个 WXML、52 个 WXSS；32 项测试通过，设计／导航／原生业务校验通过。未验证真实微信订阅和真机授权。
