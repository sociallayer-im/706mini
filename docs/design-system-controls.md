# 706 操作控件与事务页面规范

日期：2026-10-23。适用于本轮个人活动列表、个人专题、审核进度及参与方式页。关注／发现是现有视觉基准；本轮没有重新设计这两个首页。

## 依据与取舍

1. **现有关注页**：关注控件的透明按钮至少 44px 高，内部可见胶囊只有 56rpx。可见面从属于姓名、头像和内容。发现页的筛选与搜索同样是局部操作，不承担整页提交的视觉重量。实现证据：styles/community.wxss 的 person-follow / person-follow-label。
2. **仓库早期 Paper 规范**：本地历史提交 5d875ed 的 docs/design-system-paper.md 与 styles/editorial.wxss。保留「外部舒展、内部精密」、8rpx 基础单位、32rpx 内容面圆角、按语义分配字号，以及主操作至少 88rpx 的原则；紧凑操作原本就不属于整页主要操作。旧色板和描边由用户后来确认的中性块面规则取代。
3. **Figma 项目**：[卡片内操作 2:8448](https://www.figma.com/design/YSJPX7SNvnn2kGzWrbJXwo/706?node-id=2-8448) 是 112×34px、12px 文案、8px 内边距的局部操作；[按钮库 2:38182](https://www.figma.com/design/YSJPX7SNvnn2kGzWrbJXwo/706?node-id=2-38182) 的主要按钮是 327×56px、14px 文案；[分段选择 2:38037](https://www.figma.com/design/YSJPX7SNvnn2kGzWrbJXwo/706?node-id=2-38037) 将选择态与执行动作分开。已读取对应设计上下文和截图。采用其按场景分级、内容决定局部宽度、文本与操作成组的原则；当前产品的黄色、中性灰、胶囊和系统字体继续以关注／发现为准。本轮提取原则，没有复制 Figma 的登录品牌图标或媒体资产。

## 共同原则

- **点击区域与可见底色独立。** 点击区域是透明的原生 button，可见面是内部 control-face。点击高度至少 44 CSS px，紧凑可见面为 56rpx；不能把最小点击高度直接涂满成一个大按钮。
- **默认宽度由文字决定。** 不设固定 184px 宽度、半屏宽度或默认占满容器。只有 block API 才占满可用宽度。原生 mini 尺寸与组件内部的明确几何重置共同规避平台默认按钮宽度；调用页不能传任意宽高、颜色或圆角。
- **页面主次不等于业务主次。** 卡片中查看、编辑、查看二维码等是局部操作。继续编辑、付款可用紧凑黄色；同组的编辑可用文字态。整页提交和底部主操作才使用标准尺寸。
- **并列操作横向成组。** 内容足够时并排，只有文字或屏幕宽度确实不足才换行。状态说明不被做成另一个按钮；一组内最多一个黄色操作。
- **控件状态独立。** 选择态只属于筛选；loading 保留原操作的底色并拦截重复执行；disabled 才转中性。按下仅降低可见面的透明度，不缩放或改变几何。
- **内容先于操作。** 状态、标题、活动事实先组成摘要；保存时间与操作组成底部一组，减少单个按钮额外占一整行带来的空洞。

## 尺寸与职责

| 角色 | 可见面与文字 | 点击区 / 宽度 | 使用位置 |
| --- | --- | --- | --- |
| 标准 Button | 88rpx 起，body 28rpx / 500 | 至少 44px；默认随内容，block 显式开启 | 整页保存、付款、底部主行动 |
| 紧凑 Button | 56rpx 起，fact 24rpx / 500；左右 24rpx | 至少 44px；随文案自然增长 | 卡片内继续编辑、审核进度、查看二维码 |
| Danger Button | 相同字号与点击区，中性底面、danger 红字 | 随文案；不单独画轮廓 | 并列的编辑、取消报名 |
| FilterChip | 紧凑尺寸，未选白面、选中深面白字 | 独立 44px 点击区域 | 个人活动阶段筛选；横向可滚动 |
| IconButton | 正圆可见面与独立 44px 点击区 | 既有组件管几何 | 返回、关闭等图标操作 |
| ActionRow | 整行点击，统一 body 字号 | 行高与分组边界由组件管 | 活动管理入口 |

所有颜色、字号、圆角与尺寸来自 lib/theme.js。新增 controlCompactHeight / controlCompactInset / controlStandardInset / actionGap 表达角色；actionCopyMin 是说明文字与操作并列时的最小内容列，不借用海报宽高决定文本布局。长英文允许换行增高，不缩小字号。

## 本轮组件落点

- ui-button：唯一的按钮几何、可见面、主次／危险／选择态、按压与禁用机制。
- ui-filter-chip：选择语义，组合 ui-button；与执行提交的按钮区分。
- ui-personal-event：三个个人活动列表共用；ui-personal-campaign：专题列表使用同一内容／操作节奏。
- ui-access-step：编号、标题、说明与紧凑操作成组；窄屏说明和按钮允许自然换行，不强制挤成一条细列。
- 参与方式弹层的复制、完成使用 ui-button 紧凑次／文字操作，关闭使用 ui-icon-button plain；其他弹层保持各自迁移边界。
- 参与方式页的步骤属于同一个过程，共用一张白色分组面。每行编号在左、标题与说明共用文字列、紧凑操作在右；行间细线仅区分同组步骤，不为每步再套一张圆角卡。
- ui-status-summary 是只读结果摘要；其内容槽组合 ui-action-row 的 canvas 语境承载可打开的活动信息。状态图标和大标题本身不伪装成按钮。取消报名放入单独标识的「报名管理」分组，使用 danger 操作行，不在画布上悬挂一个孤立红色按钮。
- ui-review-history：活动与专题审核共用；状态／标题／说明在同一阅读流，审核记录标题位于记录之前；记录主体共用一张白面，不嵌套额外说明灰框。审核方 body 字号、时间 meta 字号；时间格式统一上海时区，禁止显示原始 ISO 字符串。

## 组件分类与实际 API

目前有 **4 类基础交互组件**，并不是每个业务文案都对应一种新按钮：

| 组件 | 对外职责 | 当前实际 API | 已使用位置 |
| --- | --- | --- | --- |
| ui-button | 执行一个明确动作 | label、variant、compact、block、context、disabled、loading；发出 press | 个人活动／专题卡、参与步骤、审核页局部操作 |
| ui-icon-button | 没有文字的图标操作 | icon、label、size、surface、disabled；发出 press | 子页返回 |
| ui-filter-chip | 选择一个筛选条件 | label、selected；发出 press；内部组合 ui-button | 我报名／我发布的活动阶段筛选 |
| ui-action-row | 整行打开内容或执行管理操作 | label、description、detail、navigation、tone、context、divider、disabled、loading；发出 press | 活动管理、参与页的活动入口与取消报名 |

ui-button 的 **4 个公开视觉变体**与尺寸、宽度互相独立：

| variant | 视觉与使用原则 |
| --- | --- |
| primary | 黄色底、深色字；当前决策区明确的下一步。同区最多一个，不因操作重要就放大。 |
| secondary | 统一浅灰底；查看、复制、并列的辅助动作，无描边。与城市入口采用相同的低强调外观。 |
| text | 透明底的文字操作；只用于已确认的轻量场景，例如评论回复。不根据“可点击”批量升格为有底色按钮。 |
| danger | 红色字、中性底面；取消、删除等破坏性操作入口。真正写入前的确认由页面流程／原生确认框处理，按钮自身不偷偷执行业务写入。 |

内部另有 selection 变体，仅供 FilterChip 组合：未选中白／灰面、选中深色面白字，selected 表达选择而非提交。业务页不直接拿它代替执行动作。

两档尺寸：compact=true 为 56rpx 可见面与 24rpx 字；默认 standard 为 88rpx 起的可见面与 28rpx 字。两者字重均 500、胶囊圆角、独立 44px 点击高度。block=false 时随文案；block=true 才填满父容器。长文案允许增高或换行，不传任意数值改宽高。当前 ui-button 尚未暴露原生 open-type，也未转发微信分享／授权事件，不能直接替换这些特殊平台按钮。

IconButton 的 surface=surface/glass/plain 分别是白色、导航同源玻璃、透明；正圆尺寸由平台导航几何或已有语义角色决定，外部点击区为 44px，纯图标必须有 label。图标按钮不是「把普通按钮缩小」。

ActionRow 的 surface 语境使用白面，canvas 语境透明且不额外内缩；description/detail 为可选事实行。只有打开另一处内容才设 navigation=true 显示同源箭头；取消报名／取消活动直接触发确认，不画导航箭头。tone=danger 只改变操作语义颜色，不创造另一套行高、圆角或字体。多行说明可使行自然增高。

业务组合组件共有 5 个：ui-personal-event、ui-personal-campaign、ui-access-step、ui-review-history、ui-status-summary。它们安排内容和权限，不定义另一套按钮皮肤。

## 状态与迁移边界

2026-10-26 账号流程补充（替代 10-24 的 compact 规则）：手机号发码／验证、微信登录、资料引导的继续／完成和欢迎页主行动统一使用 ui-button 的标准尺寸与 block 宽度。游客邀请与继续浏览按各自局部／辅助角色选用既有变体。主操作黄色，辅助操作浅灰，退出／隐私入口文字态；主次语义不改变几何。备用验证码登录也使用同一组件。全局旧按钮禁用背景仅应用于旧 class，不再涂满 ui-button 的 44px 透明点击区；共享组件明确重置外层 opacity，禁用状态由内部可见面与文字表达，避免重复变淡。参与步骤、个人活动卡和审核历史原有紧凑组件已核查，保持相同规则。头像选择保留微信原生 open-type 能力，不当作普通执行按钮迁移。

- 普通按下：140ms 的可见面透明度变化，不缩放、不加粗轮廓。
- loading：保留 variant 的身份，显示进度并阻止重复执行；页面仍使用 run 的写入保护。disabled 才改为中性色；两者不能混成一种状态。
- selected：仅属于筛选／选择控件；following 属于关注关系；都不能用 primary 的黄色替代全部状态。
- 文案、图标和布局不是新的按钮类型。图标＋文字、两按钮并列、放在浮层／卡内，均应通过已有尺寸和语境组合，不能临时新增颜色、边线和圆角。
- 关注页的 FollowControl、首页原筛选、导航项、原生分享／授权、表单原生选择器，仍有各自的模板或平台实现。它们是后续迁移对象或需要保留平台能力的控件，不应被称为已完成的全局组件库。
- 本次源码清点：screen.wxml 有 124 处原生 button 声明，sheets.wxml 有 24 处，合计 148 处。这是静态声明数，包含条件、循环、首页基准及平台特殊操作，不是屏幕上的按钮数，也不等于 148 种按钮。仍存在 primary / secondary / small / text-button / icon-button / chip 等旧 class 写法；small 只能表示尺寸，不应该继续同时决定颜色和主次。后续按使用场景逐处迁移，保留业务事件、open-type 与原生控件能力。

## 2026-10-26 表单与账号流程统一原则

这些规则适用于全局表单，包括登录、手机号、三步资料引导、常规编辑资料、活动／专题／空间创建与编辑、报名及反馈弹层。

- **复用先于逐页修补**：输入复用 ui-form-field，搜索复用 ui-search-field，选择复用 ui-select-field / ui-date-time-picker，勾选复用 ui-checkbox / ui-choice-group。页面只负责布局，不得用 input、textarea 后代选择器覆盖组件的高度、圆角、字体和内边距。常规资料编辑始终复用 pages/edit-profile/index。
- **尺寸适合内容**：控件宽度不超出父容器内容区，包含内边距和边框；缩小屏幕时可以收缩／换行。单行字段为标准控件高度，短介绍从一行起自然增高，长介绍保留适量书写空间后随内容增长；不把原生输入框默认高度或点击区域再次叠加进外框。
- **统一圆角，保护文字**：输入、搜索、下拉和日期选择采用同一 radiusField（44rpx）。标准高度呈胶囊，多行增高后保留同一固定圆角，不变成椭圆。外框负责背景、边框和圆角；原生可编辑区域不再加圆角，不裁切光标。
- **同一个文字起点**：提示文字和实际输入使用相同字号、字重、行高；光标与文字处于同一原生区域。内边距由 fieldInsetInline / fieldInsetBlock 提供，行高由 fieldLineHeight 提供；提示文字用 muted 色。不能把文字顶在圆角或边框上。输入框已表达用途时，不在引导中重复堆叠标签。
- **字数统计在框内**：字数放在外框的右下方，单独占一行，和实际编辑区域分开，不覆盖输入、光标或最后一行。计数与保存校验复用 Unicode 字符计数；一句话介绍 80 字，完整介绍 300 字。
- **勾选圆形，首行对齐**：复选框与单选均用共享圆形外观；复选仍为勾号且保持多选语义，单选仍为圆点。说明文字用次要字号／颜色，第一行的行盒与圆形同高；长文案从文字起点换行。
- **协议就在句子中**：《用户协议》和《隐私政策》使用可辨识的下划线行内链接，不额外增加一个阅读按钮。点链接只打开原文，不代替用户勾选。返回保留原步骤、输入、报名理由与同意状态，不发起报名或保存操作。
- **跨步骤共用布局**：登录、手机号、资料三步及完成页复用 accountStageHeading 和同一内容容器；标题起始高度、左右边距、说明间距一致。返回图标使用平台导航几何并与微信右侧胶囊垂直对齐。整页继续／保存为标准主按钮，局部操作保持既有尺寸和主次。
- **身份信息延续**：前一步选好的昵称与头像直接带入引导，点击原有字段可更改；预览使用明确的演示资料。欢迎页后浏览自己的主页，再复用同一编辑页补充内容。

本次源码审计覆盖全部原生 input / textarea / checkbox / radio 声明与共享表单入口。修正账号页遗留的原生字段覆盖、日期选择器圆角／字号／窄屏收缩、媒体链接方形原生输入（改用 ui-form-field）、引导及报名的协议链接，移除已废弃的第二套 onboarding 隐私／空间选择模板。搜索、常规资料、活动、专题、节点、报名、评论、举报、反馈等由共享组件获得相同的内边距、圆角、行高与宽度约束；日期、媒体上传仍保留各自原生能力。其他非输入用途的图片、通知和日历卡片不因这条输入规范改变形状。

验证：41 项单元测试、44 路由 × 2 语言全局设计检查、7 路由社区导航检查、118 项目录状态回归通过；94 个 WXML 与 53 个 WXSS 原生编译通过。在微信开发工具 iPhone mini 模拟器实看资料三步：昵称已恢复单行高度，多行输入可增高，字数留在框内，圆形勾选与首行文案对齐；实际点击行内隐私链接能阅读并返回同一步，未自动勾选。现场发现并修复微信运行时不支持 require JSON 导致协议打不开的问题（内容改为 JS 模块），修复后调试器 Errors 0。尚未逐页逐尺寸完成真机视觉走查。


## 2026-10-26 步骤切换与加载稳定性

- 活动、专题的步骤号、标题对应的字段、错误和预览必须由同一份状态计算后一次 setData；校验失败跳到错误字段时也遵循同样规则。不得先换步骤号，再渲染旧字段，随后第二次更新字段。
- 资料三步保留已经创建的原生输入、选择器和头像组件，只切换面板显隐；隐藏面板不占布局或参与交互。主按钮保留同一个实例，根据当前步骤切换动作。背景薄膜为独立且持续存在的层，不包裹频繁更新的表单内容。
- 快于 180ms 的加载不展示临时提示；慢加载仍有反馈。已有内容的刷新提示固定在导航下方，不插入正文；已有表单不能被骨架占位再次顶下去。请求完成／失败后立即收起提示，页面卸载清除等待计时。
- loading 保留按钮原有主色；只有真正禁用且未加载时才变灰。按压反馈不在切换后的下一步长时间残留。
- 首次渲染直接使用平台导航几何。登录直接提交目标阶段及已选资料、城市和字数，不先渲染一个很快被覆盖的中间阶段。

验证：45 项测试通过，包含活动／专题前进后退状态一致、资料一步更新保留输入、快慢加载计时、登录不闪现手机号中间步骤；44 路由 × 2 语言、社区导航与 118 项目录状态回归通过，94 个 WXML 和 53 个 WXSS 原生编译通过。微信模拟器实际操作资料 1→2→3→2→1，确认内容与步骤匹配、返回资料保留、隐藏面板不占空间；使用临时界面状态并恢复原主页和资料草稿，没有提交资料。尚未对全部真机进行逐帧录制验证。


## 完成页的连续性
